# 电商智能客服系统（第一章：纯对话）设计草案

日期：2026-09-24
状态：设计与实施计划已批准，实施中

## 目标与范围

本章搭建电商智能客服的纯对话闭环，先验证多轮对话、流式回复、Prompt 模板和售后描述结构化提取。聊天页面属于系统架构的一部分，纳入正式设计。

本章不加入工具调用、Agent 循环、订单查询或其他外部业务动作。客服只能基于用户提供的内容回答；信息不足时应追问，不得编造订单状态、政策或处理结果。

## 用户需求与验收

- 对话接口支持多轮会话，并通过 SSE 流式推送生成内容。
- Prompt 使用模板管理；System Prompt 明确客服身份、语气、信息边界和拒答/追问行为。
- 售后描述可被提取为固定 JSON 字段：订单号、诉求类型、期望方案。
- 对话上下文采用简单的历史裁剪和 token 预算控制。
- 模型通过统一 OpenAI 协议接入上游；提供商地址、模型名、密钥来自 `.env`，覆盖 GPT、Claude、DeepSeek 和 Ollama。
- 前端采用 Vue 3、TypeScript、Pinia，提供可用的聊天页面及流式消息展示。

验收以三条主路径为准：curl 可看到 SSE 回复；第二轮对话能够使用第一轮上下文；售后描述接口返回字段齐全的结构化 JSON。

## 方案

### 后端

使用 Python、FastAPI 和 LangChain。对话 API 接受会话标识和本轮消息，服务端读取该会话历史、按 token 预算裁剪，再将历史与本轮输入交给带有 System Prompt 的 PromptTemplate。模型输出通过 SSE 持续传给客户端；完成后将用户消息和助手回复写入本章采用的会话存储。

本章会话存储使用进程内存储，以便跑通多轮闭环；重启后会话丢失属于已知限制。接口和存储边界应避免把进程内实现暴露为永久存储承诺。

另设售后描述结构化提取能力，输入自然语言描述，输出固定字段的 JSON。使用 LangChain 的 `with_structured_output` 能力约束结果结构；此功能只做信息提取，不调用订单系统或执行售后操作。

### 模型配置

由 `.env` 配置 OpenAI 兼容的 base URL、模型名、API key，以及必要的超时或 token 预算参数。应用侧使用统一协议与模型交互，支持 GPT、Claude、DeepSeek、Ollama。不得在代码中硬编码密钥。具体环境变量名、依赖版本和各提供商兼容性在实现计划阶段根据 Context7 官方文档核实后确定。

### 前端

采用 Vue 3、TypeScript、Pinia。聊天页提供消息列表、输入区、发送状态和逐段追加的流式回复；前端发送会话标识和本轮消息，后端从进程内存读取历史，前端处理 SSE 内容并展示错误/结束状态。页面先按清晰、易验证的纯对话流程实现，不扩展工具面板或订单操作交互。

## 接口草案

- `POST /api/chat/stream`：输入 `conversation_id`（新会话可为空）、`message`；返回 SSE 事件流，使用 `token` 事件逐段发送文本，`done` 事件携带会话标识表示完成，`error` 事件表示出错。
- `POST /api/after-sales/extract`：输入售后描述；返回 `order_id`、`request_type`、`preferred_resolution` 三个字段。字段缺失时使用 JSON `null`。

请求与响应的精确 schema、错误码留待计划阶段结合官方 API 文档定稿；SSE 事件名已按上述约定确定。

## Prompt 约束

System Prompt 将客服描述为电商售后客服，要求其礼貌、简洁、先理解诉求；只能依据对话中提供的信息作答；不得臆造订单、物流、退款进度或平台规则；缺少订单号、问题细节或处理偏好时，逐项追问；不承诺已执行任何外部操作。普通聊天提示与结构化提取提示分开管理。

## 上下文与 token 预算

每次请求保留 System Prompt 和当前用户消息，优先保留最近的完整对话轮次；超出配置预算时从最旧的历史轮次开始裁剪，不截断当前用户消息。预算需为模型输出留出空间。使用 `tiktoken` 的 `cl100k_base` 对所有兼容上游作统一近似计数；该值不是 Claude、DeepSeek 或 Ollama 的精确 provider tokenizer 计数。若当前输入本身超过估算后的可用预算，应返回可理解的输入过长错误，而不是静默丢弃内容。

## 失败处理

上游配置缺失、连接失败或生成中断时，API 返回可辨识的错误；SSE 已开始后以错误事件结束流，不伪装成完整回答。结构化输出解析失败时返回服务错误，不返回看似成功但字段不合规的数据。日志不得记录密钥。

## 验证方式

- 使用标注样例/小型评估集验证 System Prompt 边界行为与售后字段提取；记录样例、期望值和实际结果。
- 对纯逻辑部分按计划采用测试驱动开发。
- 人工或浏览器验证聊天页面能显示逐段回复、发送状态和错误状态。
- 按验收命令验证 SSE、多轮上下文和结构化 JSON。

## 明确不包含

工具调用、Agent 循环、检索增强、订单/物流系统连接、账号认证、持久化会话数据库、售后动作执行、复杂管理后台。
